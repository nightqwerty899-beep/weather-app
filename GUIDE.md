# Лабораторная 3: гайд по коду и стратегия защиты

Уровень: «Отлично». Выполнены все условия: модули, свой debounce, кеш на сессию, отдельное поведение для ошибок «нет сети», «ничего не найдено», «что-то пошло не так», с выводом кода ошибки на экран.

## Часть 0. Как запускать

ES-модули (`import`/`export`) не работают при открытии через `file://`. Нужен http-сервер:

```
cd weather
npx serve .          # или: python3 -m http.server 8000
```

Затем открыть `http://localhost:8000`. Если на защите открыть `index.html` двойным кликом, будет ошибка CORS, и это нормально. Скажи, что нужен сервер, потому что браузер блокирует загрузку модулей с `file://`.

## Часть 1. Что изменилось относительно твоего script3.js

| Было (script3.js) | Стало |
|---|---|
| Один файл ~225 строк, всё вперемешку | 6 модулей по ответственности + `main.js` |
| Нет debounce | Свой `debounce` в `utils.js`, применён к поиску подсказок |
| Кеша нет, повторный город = новый запрос | `cache.js` на `Map`, TTL 5 минут, лимит 5 записей |
| Ошибки: 404, 401, «Ошибка запроса: N» | 3 вида ошибок + код на экране + нет сети |
| `JSON.parse(localStorage.getItem(..) \|\| [])` | Исправлено на `\|\| '[]'` (в старом коде `[]` превращалось в пустую строку, и парс падал) |
| `unique.push` + `slice(0,5)` оставлял самые старые города | `unshift`: новые города в начале |
| Кнопки доступны во время запроса | Блокируются через `disabled` |
| Один запрос `/forecast` | Два: `/weather` (сейчас) и `/forecast` (5 дней), как в лекции |
| Анимация `rotate(1440deg)` | `rotate(360deg)` |
| `[hidden]` закомментирован в CSS | Включён: `[hidden]{display:none !important}` |

Структура:

```
weather/
├─ index.html    разметка, подключает main.js как module
├─ style.css     стили (твои + подсказки + disabled)
├─ main.js       события, связка модулей, сценарии ошибок
├─ api.js        fetch, ApiError, статусы
├─ ui.js         DOM
├─ storage.js    история в localStorage
├─ cache.js      кеш на Map
└─ utils.js      debounce, minutes, hPaToMmHg, pickDailyForecast
```

Граф зависимостей (стрелки в одну сторону, циклов нет):

```
main.js ──► api.js
   │──────► ui.js ──► utils.js
   │──────► cache.js ──► utils.js
   │──────► storage.js
   └──────► utils.js
```

## Часть 2. Построчный разбор

### 2.1 utils.js

```js
export function debounce(fn, delay) {
```
Принимает функцию `fn`, которую надо «притормозить», и паузу `delay` в мс. `export` делает функцию видимой снаружи модуля.

```js
  let timer;
```
Переменная живёт между вызовами, потому что её держит замыкание. У каждого `debounce(...)` свой `timer`.

```js
  return (...args) => {
```
Возвращаем новую функцию. Именно её вешаем на событие. `...args` собирает все аргументы (например, объект события).

```js
    clearTimeout(timer);
```
Отменяем предыдущий запланированный запуск, который не успел сработать. Если таймера нет или он уже сработал, `clearTimeout` ничего не делает и не падает.

```js
    timer = setTimeout(() => fn(...args), delay);
```
Планируем запуск заново через `delay` мс и передаём аргументы дальше. Итог: `fn` выполнится, только если `delay` мс подряд не было новых вызовов.

```js
const countryNames = new Intl.DisplayNames(['ru'], { type: 'region' });
export function countryName(code) { return countryNames.of(code) || code; }
```
`Intl.DisplayNames` встроенный API браузера: переводит код страны в название (`RU` → «Россия»). Объект создаём один раз вне функции.

```js
export function mergeSuggestions(cached, fromApi) {
  const seen = new Set();
  return [...cached, ...fromApi].filter((c) => {
    const key = `${c.name.toLowerCase()}|${c.country}`;
    if (seen.has(key)) return false;
    seen.add(key);
    return true;
  });
}
```
Склеивает два списка: сначала города из кеша, потом из API (spread `...` копирует элементы в новый массив). `filter` с `Set` оставляет только первое вхождение пары «имя + страна», поэтому «Москва» из кеша не дублируется «Москвой» из API. Это чистая функция, её легко тестировать.

```js
export function minutes(n) { return n * 60 * 1000; }
```
Мс = минуты × 60 × 1000. Нужна для читаемости: `minutes(5)` понятнее, чем `300000`.

```js
export function hPaToMmHg(hPa) { return Math.round(hPa * 0.75006); }
```
API отдаёт давление в гПа, в России привычны мм рт. ст. Коэффициент 0.75006. Это чистая функция: нет DOM, сети и хранилища, поэтому её легко тестировать.

```js
export function pickDailyForecast(list, daysCount = 5) {
```
API `/forecast` отдаёт 40 записей (5 дней × 8 по каждые 3 часа). Нам нужна одна запись на день.

```js
  const byDay = new Map();
```
Ключ: дата `YYYY-MM-DD`, значение: выбранная запись.

```js
  list.forEach((item) => {
    const date = new Date(item.dt * 1000);
```
`dt` в API это секунды Unix, а `Date` ждёт миллисекунды, поэтому `* 1000`.

```js
    const key = date.toISOString().slice(0, 10);
```
`toISOString()` даёт `2026-10-05T12:00:00.000Z`, первые 10 символов это дата.

```js
    const saved = byDay.get(key);
    if (!saved) { byDay.set(key, item); return; }
```
Первая запись дня сохраняется сразу.

```js
    const savedHour = new Date(saved.dt * 1000).getHours();
    if (Math.abs(date.getHours() - 12) < Math.abs(savedHour - 12)) {
      byDay.set(key, item);
    }
```
Если новая запись ближе к полудню, чем сохранённая, заменяем её. В итоге остаётся запись, ближайшая к 12:00.

```js
  return [...byDay.values()].slice(0, daysCount);
```
Превращаем значения `Map` в массив и берём первые 5. `Map` хранит порядок вставки, поэтому дни идут по порядку.

### 2.2 cache.js

```js
import { minutes } from './utils.js';
```
Импорт по относительному пути. Расширение `.js` в браузерных модулях обязательно.

```js
export const TTL = minutes(5);
```
TTL (time to live) это срок жизни записи. Экспортируем, чтобы `main.js` знал, когда данные устареют.

```js
const MAX = 5;
const cache = new Map();
```
`MAX` и `cache` без `export`: это внутренности, наружу не торчат (ценность границ). Сам кеш это просто переменная, поэтому он живёт, пока открыта вкладка, и пропадает при перезагрузке (по заданию «можно только на время сессии»).

```js
export function cacheGet(key) {
  const entry = cache.get(key);
  if (!entry) return null;
```
Нет записи: возвращаем `null`.

```js
  if (Date.now() - entry.time > TTL) {
    cache.delete(key);
    return null;
  }
  return entry;
```
Запись старше TTL: удаляем и тоже возвращаем `null`. Иначе отдаём запись. Протухшие записи чистятся лениво, при обращении.

```js
export function cacheSearch(query) {
  const q = query.trim().toLowerCase();
  const result = [];
  for (const [key, entry] of cache) {
    if (Date.now() - entry.time > TTL) continue;
    const name = entry.current.name;
    if (key.startsWith(q) || name.toLowerCase().startsWith(q)) {
      result.push({ name, country: countryName(entry.current.sys.country) });
    }
  }
  return result.reverse();
}
```
Подсказки из кеша: идём по записям (`for...of` по `Map` даёт пары `[ключ, значение]`), пропускаем протухшие, берём те, у которых ключ или название начинается с введённого. `result.reverse()` разворачивает порядок: `Map` хранит от старых к новым, а нам нужны самые свежие первыми. Название берём из ответа API (`entry.current.name`), оно уже на русском, потому что в запросе `lang=ru`.

```js
export function cacheSet(key, data) {
  cache.delete(key);
```
Удаляем старую запись с этим ключом, чтобы после `set` она стала самой новой в порядке `Map`. Без этого обновлённый город мог бы вытесниться первым.

```js
  const entry = { ...data, time: Date.now() };
  cache.set(key, entry);
```
Копируем данные и добавляем время сохранения.

```js
  if (cache.size > MAX) {
    cache.delete(cache.keys().next().value);
  }
  return entry;
```
Если записей больше 5, удаляем самую старую. `cache.keys()` это итератор в порядке вставки, `.next().value` даёт первый (самый старый) ключ. Это FIFO-вытеснение. Возвращаем `entry`, чтобы вызывающий код получил `time`.

### 2.3 storage.js

```js
const KEYS = { history: 'weather_last_cities', lastCity: 'weather_last_city' };
const HISTORY_LIMIT = 5;
```
Ключи `localStorage` вынесены в константы, чтобы не опечататься строкой.

```js
export function getHistory() {
  try {
    const parsed = JSON.parse(localStorage.getItem(KEYS.history) || '[]');
```
`localStorage` хранит только строки. Если ключа нет, `getItem` вернёт `null`, подставляем строку `'[]'`, и парс даёт пустой массив.

```js
    return Array.isArray(parsed) ? parsed.filter((c) => typeof c === 'string') : [];
```
Защита от битых данных: вдруг там объект или число. Принимаем только массив строк.

```js
  } catch { return []; }
```
Если в хранилище лежит мусор вроде `{`, `JSON.parse` бросит `SyntaxError`, и мы вернём пустую историю. Это сценарий «битые данные в хранилище» из лекции.

```js
export function saveCity(city) {
  const name = city.trim();
  if (!name) return getHistory();
```
Пустую строку не сохраняем.

```js
  const history = getHistory().filter((c) => c.toLowerCase() !== name.toLowerCase());
  history.unshift(name);
  const limited = history.slice(0, HISTORY_LIMIT);
```
Убираем дубликат без учёта регистра («москва» и «Москва» это один город), ставим город в начало (`unshift`), оставляем 5 последних.

```js
  try {
    localStorage.setItem(KEYS.history, JSON.stringify(limited));
    localStorage.setItem(KEYS.lastCity, name);
  } catch { }
  return limited;
```
`JSON.stringify` превращает массив в строку. `try/catch` нужен, потому что `setItem` может бросить исключение (приватный режим, переполнение квоты). Возвращаем актуальный список, чтобы `main.js` сразу отрисовал его.

```js
export function getLastCity() { ... localStorage.getItem(KEYS.lastCity) || '' ... }
```
Последний город для автоподстановки при старте. Обёрнуто в `try/catch` по той же причине.

### 2.4 api.js

```js
const API_KEY = '...'; const BASE = 'https://api.openweathermap.org';
```
Ключ и адрес в одном месте. Если сменится провайдер, правим только этот файл (доменная ценность). Ключ и в учебной работе лежит на клиенте; в реальном проекте его прячут на бэкенде.

```js
export const ERROR_KIND = { NETWORK: 'network', NOT_FOUND: 'not_found', OTHER: 'other' };
```
Три вида ошибок из задания. Используем константы вместо «магических строк».

```js
export class ApiError extends Error {
  constructor(kind, message, status = null) {
    super(message);
```
Свой класс ошибки наследует `Error`. `super(message)` обязательно вызывается первым, он задаёт `err.message`.

```js
    this.name = 'ApiError';
    this.kind = kind;
    this.status = status;
```
Добавляем вид ошибки и HTTP-код. У «нет сети» кода нет, поэтому `null`.

```js
function messageForStatus(status, city) {
  if (status === 404) return `Город «${city}» не найден`;
  if (status === 401 || status === 403) return 'Проблема с ключом API';
  if (status === 429) return 'Слишком много запросов...';
  if (status >= 500) return 'Сервер недоступен...';
  return 'Не удалось получить данные';
}
```
Таблица из лекции «код → сообщение». Функция не бросает ошибку, она только выбирает текст.

```js
async function request(url, { city = '', signal } = {}) {
```
Единая точка запроса: все сценарии ошибок сходятся здесь (принцип DRY). `signal` нужен для отмены, `city` для текста сообщения.

```js
  let response;
  try { response = await fetch(url, { signal }); }
```
Объявляем `response` снаружи `try`, чтобы использовать ниже.

```js
  catch (err) {
    if (err.name === 'AbortError') throw err;
```
Отмена через `AbortController` это не ошибка пользователя. Пробрасываем как есть, и вызывающий код её тихо игнорирует.

```js
    throw new ApiError(ERROR_KIND.NETWORK, 'Нет соединения с интернетом');
  }
```
`fetch` отклоняет промис только при сетевом сбое (оффлайн, DNS, блокировка запроса). Поэтому любой другой `catch` здесь означает «нет сети».

```js
  if (!response.ok) {
```
Ключевой момент лекции: `fetch` не бросает ошибку на 404 или 500. `response.ok` это `true` для статусов 200–299.

```js
    const kind = response.status === 404 ? ERROR_KIND.NOT_FOUND : ERROR_KIND.OTHER;
    throw new ApiError(kind, messageForStatus(response.status, city), response.status);
  }
```
404 это «ничего не найдено», всё остальное это «что-то пошло не так». Код передаём в ошибку, чтобы вывести на экран.

```js
  try { return await response.json(); }
  catch { throw new ApiError(ERROR_KIND.OTHER, 'Сервер вернул некорректный ответ', response.status); }
```
Если сервер ответил 200, но не JSON (например, HTML-заглушка прокси), это тоже «что-то пошло не так». `await` внутри `try` обязателен, иначе `catch` не поймает.

```js
function params(extra) {
  return new URLSearchParams({ appid: API_KEY, units: 'metric', lang: 'ru', ...extra });
}
```
`URLSearchParams` собирает query-строку и сам кодирует спецсимволы (кириллицу, пробелы). Общие параметры в одном месте, специфичные через `...extra`.

```js
export function getWeather(city) { return request(`${BASE}/data/2.5/weather?${params({ q: city })}`, { city }); }
export function getForecast(city) { ... /forecast ... cnt: 40 ... }
```
Текущая погода и прогноз на 5 дней (40 записей по 3 часа). Функции не `async`, они просто возвращают промис из `request`.

```js
export async function getCitySuggestions(query, signal) {
  const url = `${BASE}/geo/1.0/direct?${params({ q: query, limit: 5 })}`;
  const data = await request(url, { city: query, signal });
  return data.map((c) => ({ name: c.local_names?.ru || c.name, country: countryName(c.country) }));
}
```
Geocoding API ищет города по началу названия, до 5 штук. Русское название берём из `local_names.ru` (`?.` защищает от `undefined`), если его нет, остаётся `name`. Страна переводится на русский функцией `countryName` из `utils.js`. Наружу возвращаем только `name` и `country`.

### 2.5 ui.js

```js
import { hPaToMmHg, pickDailyForecast } from './utils.js';
const $ = (id) => document.getElementById(id);
```
Короткий помощник для поиска элементов. Импортируем только то, что нужно. `fetch` в этом файле нет (правило проекта).

```js
export const els = { cityInput: $('cityInput'), ... suggestions: $('suggestions') };
```
Все элементы ищем один раз при загрузке модуля. Модуль подключён через `type="module"`, поэтому выполняется после разбора HTML и элементы уже есть. `main.js` вешает слушатели на `ui.els.*`.

```js
export function setLoading(isLoading) {
  els.loader.hidden = !isLoading;
  els.getBtn.disabled = isLoading;
  els.refreshBtn.disabled = isLoading;
  if (isLoading) els.weather.hidden = true;
}
```
Один флаг управляет крутилкой и блокировкой обеих кнопок. Это сценарий «клик во время запроса» из лекции. Прошлый результат прячем, чтобы не видеть старые данные поверх загрузки.

```js
export function showError(message, status = null) {
  els.error.textContent = status ? `${message} (код ошибки: ${status})` : message;
}
```
Код ошибки выводится на экран, как требует «Отлично». Для «нет сети» кода нет, поэтому скобки не добавляются. Используем `textContent`, а не `innerHTML`: текст ошибки не интерпретируется как HTML (защита от XSS).

```js
showStatus / hideStatus / clearError / hideWeather
```
Из твоего старого кода: информационное и предупреждающее сообщение (синее и оранжевое).

```js
export function renderCurrent(current) {
  els.cityName.textContent = `${current.name}, ${current.sys.country}`;
```
В ответе `/weather` название в `name`, страна в `sys.country` (в `/forecast` было `city.name`, поэтому формат отличается).

```js
  const stats = [ { label: 'Температура', value: `${Math.round(current.main.temp)}°C` }, ... ];
  els.todayStats.innerHTML = stats.map((s) => `...`).join('');
```
Пять карточек данными, а не HTML вручную. `map` превращает каждую в строку HTML, `join('')` склеивает. Здесь `innerHTML` безопасен, потому что значения числовые и из нашего шаблона.

```js
export function renderForecast(forecast) {
  els.forecastList.innerHTML = '';
  pickDailyForecast(forecast.list).forEach((item) => { ... createElement('div') ... appendChild(card) });
  els.weather.hidden = false;
```
Чистим список, выбираем по записи в день, строим карточки. Дата форматируется `toLocaleDateString('ru-RU', ...)`. В конце показываем блок погоды целиком, то есть показ происходит после успешной отрисовки.

```js
export function renderHistory(cities, onSelect) {
  ...
  button.addEventListener('click', () => onSelect(city));
```
`onSelect` это колбэк. `ui.js` не знает про `main.js` и `loadWeather`, поэтому круговой зависимости нет (приём из лекции). Если история пуста, показываем «Пока пусто».

```js
export function renderSuggestions(cities, onSelect) {
  ...
  li.addEventListener('mousedown', (e) => { e.preventDefault(); onSelect(c.name); });
```
Порядок событий мыши: `mousedown` → `blur` у input → `click`. Если слушать `click`, на `blur` мы уже спрячем список и клик не сработает. `mousedown` приходит раньше, `preventDefault` не даёт input потерять фокус.

```js
export function hideSuggestions() { els.suggestions.hidden = true; els.suggestions.innerHTML = ''; }
```

### 2.6 main.js

Вверху файла две константы: `MIN_CHARS = 2` (с скольких символов показываем подсказки) и `SUGGEST_DELAY = 400` (пауза после последней буквы). Их можно менять в одном месте.

```js
import { getWeather, getForecast, getCitySuggestions, ApiError, ERROR_KIND } from './api.js';

...
```

`main.js` знает про все модули, они про него нет. `import * as ui` собирает все экспорты в один объект-пространство имён.

```js
let changeTimer = null;

let isLoading = false;
```

#### loadWeather

```js

  if (isLoading) return;
```

Страховка от двойного запроса: кнопки уже заблокированы, но Enter в поле ввода или клик по истории всё ещё могут сработать. Блокировка в интерфейсе и защита в коде это две независимые защиты.

## Часть 5. Вопросы и ответы по лекции

### Модули

**Зачем делить код на файлы?** Чтобы менять одно, не читая всё. Четыре ценности из лекции: *смысловая* (имя файла говорит, что внутри), *доменная* (код одной области лежит вместе, смена поставщика погоды правится в одном файле), *границ* (снаружи виден только `export`, внутренности можно переписать), *командная* (меньше git-конфликтов, функцию можно проверить отдельно и взять в другой проект).

**По какому принципу делить: по размеру или по ответственности?** По ответственности. Проверка: можно ли сказать, что делает файл, одним предложением без «и».

**Какие два правила проекта?** `ui.js` не делает `fetch`, `api.js` не трогает DOM. Нарушение значит, что код лежит не в том домене.

**Что такое «стрелки в одну сторону» и циклические зависимости?** `main.js` импортирует `api.js` и `ui.js`, они его нет. Круг a ↔ b лечится колбэком, как `onSelect` в `renderHistory`.

**Что делает `export`? Что будет, если его не написать?** Делает имя доступным другим модулям. Без него импорт даст `SyntaxError: does not provide an export named...`.

**Что такое именованный и default-экспорт? Что у тебя?** Именованный: `export function a`, импорт в `{}` с тем же именем. Default: `export default`, импорт с любым именем. У меня именованные. `import * as ui` собирает все именованные в объект.

**Почему нужен `type="module"`?** Без него `import` это синтаксическая ошибка. Модули ещё отложены (как `defer`), в строгом режиме, с изолированной областью видимости.

**Почему открытие через `file://` не работает?** Браузер блокирует загрузку модулей по `file://` из-за CORS. Нужен http-сервер.

**Почему в пути `./api.js` обязательно `./` и `.js`?** Браузер понимает только пути к файлам. `./` значит «рядом». Без расширения браузер не угадывает файл (в отличие от Node или сборщика).

**Чем модуль отличается от обычного скрипта?** Своя область видимости (переменные не глобальны), строгий режим, выполняется один раз (повторный импорт отдаёт тот же экземпляр), поддерживает `import/export`.

**Если два файла импортируют `cache.js`, будет ли два кеша?** Нет, модуль выполняется один раз, `cache` общий. Так и работает singleton.

### Статусы ответа и ошибки

**`fetch` бросает ошибку на 404?** Нет. Он отклоняется только при сетевом сбое. Статус проверяем сами через `response.ok` (true для 200–299).

**Как отличить «нет сети» от «сервер ответил ошибкой»?** Нет сети: `fetch` отклонился (`catch`), ответа нет, кода нет. Сервер ответил ошибкой: ответ пришёл, `ok === false`, есть `status`.

**Таблица кодов, чья проблема и что делать?**
- 401 / 403: нет доступа (ключ неверный или отключён), проблема наша, повтор бесполезен.
- 404: не найдено, проблема пользователя (опечатка).
- 429: слишком много запросов, наша проблема, подождать и повторить.
- 500–503: сервер сломан или перегружен, проблема сервера, попробовать позже.

**Чем 401 отличается от 403?** 401 не аутентифицирован (ключ не принят), 403 аутентифицирован, но нет прав. Для пользователя обработка одна.

**Как ты реализовал три вида ошибок из задания?** `ApiError` с полем `kind`: `network`, `not_found`, `other`. `handleError` в `main.js` делает `switch` по `kind`, у каждого свой текст.

**Зачем свой класс `ApiError`?** Чтобы нести структуру (вид, код, сообщение), различать наши ошибки через `instanceof` и не разбирать строки.

**Зачем `try/catch` вокруг `response.json()`?** Сервер может вернуть 200 с телом не в JSON (заглушка прокси). Без этого упадёт необработанная ошибка.

**Как воспроизводил ошибки?** Таблица из части 3: DevTools Offline, Block request URL, Throttling, `httpbin.org/status/N`, испорченный ключ.

**Почему не показываешь код для «нет сети»?** Кода просто нет: HTTP-ответа не было.

**Что произойдёт при отказе только одного из двух запросов?** `Promise.all` отклоняется на первой же ошибке, показываем ошибку, ничего не кешируем и не сохраняем в историю.

### Debounce

**Что такое debounce?** Функция выполняется только после паузы в вызовах. Каждый новый вызов сбрасывает таймер.

**Зачем он нужен?** Без него слово из шести букв даёт пять запросов: впустую тратится лимит API, список подсказок мигает.

**Объясни свой код.** `timer` в замыкании, возвращаем функцию, `clearTimeout` отменяет прошлый запуск, `setTimeout` планирует новый с `...args`.

**Что такое замыкание и где оно здесь?** Функция помнит переменные из области, где создана. Возвращённая функция помнит `timer` и `fn` даже после выхода из `debounce`.

**Почему 400 мс?** Диапазон 300–500: короче запросы не экономятся, длиннее интерфейс кажется вялым.

**Типичная ошибка при подключении?** Вызывать `debounce(...)()` внутри обработчика: каждый раз создаётся новый таймер, сбрасывать нечего. Создавать нужно один раз вне обработчика.

**Debounce или throttle?** Debounce: «выполнить после паузы» (поиск, resize в конце). Throttle: «не чаще раза в N мс» (scroll, прогресс).

**Зачем `...args`?** Чтобы передать в `fn` аргументы события.

**Почему нельзя взять lodash?** Условие лабы: библиотечную нельзя.

**Решает ли debounce гонку запросов?** Нет. Он уменьшает число запросов, но на медленной сети ответ на «Ом» может прийти после «Омск» и перетереть список. Это решает `AbortController`.

### AbortController

**Как работает отмена?** `new AbortController()` даёт `signal`. Передаём его в `fetch`. `controller.abort()` отклоняет промис с `AbortError`.

**Почему `AbortError` не показываешь пользователю?** Это значит «пришёл более свежий запрос», а не сбой.

**Можно ли переиспользовать контроллер?** Нет, после `abort()` он остаётся в состоянии «отменён». На каждый запрос новый.

**Зачем `?.` в `suggestController?.abort()`?** При первом вызове контроллера ещё нет (`null`).

### Кеш

**Что такое кеш и зачем?** Копия ответа, чтобы не спрашивать сервер дважды: быстрее, дешевле (дальше до лимита 429), меньше нагрузки на чужой API.

**Цена кеша?** Данные устаревают. Отсюда TTL и кнопка «Обновить».

**Что такое TTL?** Срок жизни записи. У меня 5 минут: старше, значит протухла, удаляется, идём на сервер.

**Какой ключ и почему?** Название города в нижнем регистре, чтобы «Москва» и «москва» были одной записью.

**Почему `Map`, а не объект?** `Map` помнит порядок вставки (нужно для вытеснения самой старой записи), у него удобные `size`, `delete`, `keys`, нет коллизий с прототипом (`toString`, `constructor`), ключом может быть что угодно.

**Как вытесняется старое?** `cache.delete(cache.keys().next().value)`: `keys()` отдаёт ключи в порядке вставки, первый это самый старый. Это FIFO. Для LRU при каждом чтении надо было бы переставлять запись в конец.

**Зачем `cache.delete(key)` перед `set`?** Если ключ уже есть, `Map.set` не меняет его позицию. Удаление делает обновлённую запись самой новой.

**Кешируешь ли ошибки?** Нет. Только успешные ответы. Иначе одна ошибка (например, обрыв сети) застряла бы на 5 минут.

**Где кеш подводит?** Устаревшие данные, разные ключи («Moscow» и «Москва»), память вкладки (после перезагрузки пуст), ошибки.

**Чем кеш в `Map` отличается от `localStorage`?** `Map` живёт в памяти вкладки и пропадает при перезагрузке, это достаточно по условию («на время сессии»). `localStorage` переживает перезагрузку, хранит только строки, лимит около 5 МБ. История городов у меня в `localStorage`, кеш в `Map`.

**Как работает «Обновить» с кешем?** `loadWeather(city, { force: true })`: `entry = null`, кеш пропускается, новые данные перезаписывают запись.

**Что значит «один источник» в `loadWeather`?** Неважно, пришли данные из кеша или с сервера, дальше одна и та же отрисовка.

**Почему `Promise.all`?** Два запроса независимы, идут параллельно: время равно максимуму, а не сумме.

**Шутка про кеш?** Две сложные вещи в программировании: инвалидация кеша и имена переменных.

### Сборщик (последний раздел лекции)

**Какая проблема?** `import dayjs from "dayjs"` в браузере даёт `Failed to resolve module specifier "dayjs". Relative references must start with "/", "./" or "../"`: браузер понимает только пути к файлам, а пакет лежит в `node_modules` (npm).

**Что такое сборщик?** Посредник, который находит пакеты, разрешает импорты и собирает всё для браузера (Vite из плана лекции). Типичные плюсы: разрешение npm-пакетов, склейка и минификация файлов, дев-сервер с горячей перезагрузкой.

**Нужен ли сборщик в твоей лабе?** Нет: используются только собственные файлы с относительными путями, внешних npm-пакетов нет, поэтому хватает обычного http-сервера. (Если вспомнишь детали Vite, которых нет в слайдах, говори осторожно.)

### Общие по JS

**Что делает `async/await`?** Синтаксис над промисами. `await` приостанавливает функцию до завершения промиса, не блокируя страницу.

**Что вернёт async-функция?** Всегда промис. `throw` внутри это отклонение.

**Что делает `finally`?** Выполняется в любом случае: при успехе, ошибке и `return`. Я сбрасываю там `isLoading`.

**`textContent` или `innerHTML`?** `textContent` вставляет текст как есть (безопасно), `innerHTML` разбирает HTML (риск XSS, если вставлять пользовательские данные).

**`hidden` и `display:none`?** `hidden` это атрибут, но CSS `display:flex` у класса его перебивает, поэтому нужна строка `[hidden] { display:none !important }`.

**Что делает `encodeURIComponent` / `URLSearchParams`?** Экранируют спецсимволы и кириллицу в адресе. Я использую `URLSearchParams`.

**Что такое `localStorage` и чем отличается от `sessionStorage`?** Хранилище «ключ-строка» в браузере. `localStorage` живёт после закрытия вкладки, `sessionStorage` до закрытия вкладки.

**Чем `mousedown` отличается от `click`?** `click` приходит после `mousedown` и `mouseup`. По дороге срабатывает `blur`, который прячет список, поэтому подсказки ловят `mousedown`.

## Часть 6. Вопросы по самой лабе

**Какие критерии оценки и что выполнено на «Отлично»?** «Хорошо»: модули, свой debounce, кеш на сессию. «Отлично»: плюс отдельное поведение для «нет сети», «ничего не найдено», «что-то пошло не так», с выводом кода ошибки на экран. Всё выполнено.

**Где у тебя debounce и где он применён?** `utils.js`, подключён в `main.js` к событию `input` поля поиска. Он вызывает подсказки городов.

**Почему debounce к подсказкам, а не к кнопке «Получить погоду»?** Debounce нужен там, где запрос идёт на каждое нажатие клавиши. Кнопка это одно намеренное действие, ей защита нужна другая: блокировка во время запроса.

**Где кеш и что в нём?** `cache.js`. Ключ: город в нижнем регистре. Значение: `{ current, forecast, time }`.

**Что такое «кеширование на время сессии»?** Данные в памяти страницы, исчезают при перезагрузке. У меня это переменная `Map` внутри модуля.

**Как показать преподавателю, что кеш работает?** Network: Москва, Омск, Москва. Третий раз запросов нет, на экране «Данные из кеша».

**Почему просмотренные города в подсказках идут первыми?** `cacheSearch` берёт их из кеша, они показываются сразу, а `mergeSuggestions` ставит их перед результатами API. Для пользователя это быстрее и удобнее: города, которые он смотрел, он будет искать чаще.

**Ограничение этой фичи?** Кеш ищется по введённому названию и по русскому названию из ответа, поэтому город, найденный по английскому «Moscow», в подсказках покажется как «Москва», но при выборе ключ кеша будет «москва» и запрос уйдёт на сервер заново. Это то же ограничение «разные ключи» из лекции.

**Как показать, что debounce работает?** Network, фильтр `geo`: набрать «Москва» без пауз, виден один запрос.

**Что выводится на экране при ошибке?** Сообщение и код: «… (код ошибки: 404)». Для «нет сети» без кода.

**Какое уведомление «Погода изменилась»?** Из твоего исходника: через 5 минут после получения данных показывается предупреждение, что данные могли устареть, с призывом нажать «Обновить».

**Что бы ты улучшил?** Хранить кеш в `sessionStorage`, чтобы он переживал перезагрузку вкладки. Нормализовать ключи («Moscow» и «Москва»). Спрятать API-ключ на бэкенде. Автотесты на `debounce`, кеш и `request`. Повтор запроса при 5xx с задержкой. Вытеснение по LRU.

**Почему два запроса вместо одного, как было?** Как в лекции («один город, 2 запроса: погода и прогноз»). `/weather` даёт актуальную погоду сейчас, `/forecast` даёт прогноз на 5 дней. Раньше «сегодня» брали из первой записи прогноза (она может быть до 3 часов старой).

**Какие баги ты нашёл и исправил в исходном коде?**
1. `JSON.parse(localStorage.getItem(...) || [])`: если ключа нет, `[]` превращалась в пустую строку, и парс падал в `catch`. Теперь `|| '[]'`.
2. `unique.push` + `slice(0,5)` оставляли самые старые города (после пятого новые не помещались). Теперь `unshift`.
3. Анимация `rotate(1440deg)` крутила 4 оборота за секунду. Теперь 360.
4. `[hidden]` был закомментирован: в исходнике это не ломало вёрстку, но любой элемент с `display:flex/grid` (например, список подсказок) с `hidden` остался бы видимым. Правило включено заранее.
5. Кнопки не блокировались во время запроса: можно было отправить несколько запросов.
6. Текст ошибки 401 ссылался на `script.js`, которого нет.
